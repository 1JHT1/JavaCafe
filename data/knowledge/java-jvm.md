# Java JVM 面试知识

## JVM 内存区域划分

JVM 运行时内存区域分为线程私有与线程共享两类。

线程私有：程序计数器、虚拟机栈、本地方法栈。线程共享：堆、方法区（JDK 8 后为元空间 Metaspace）。

- 程序计数器：记录当前线程执行的字节码行号，是唯一不会发生 OOM 的区域。
- 虚拟机栈：存放栈帧，每个方法调用对应一个栈帧，栈帧包含局部变量表、操作数栈、动态链接、方法出口。栈深度超过限制抛出 StackOverflowError，动态扩展失败抛出 OutOfMemoryError。
- 本地方法栈：为 native 方法服务，HotSpot 中与虚拟机栈合并。
- 堆：对象实例与数组的分配区域，也是 GC 的主要区域，可细分为新生代（Eden、Survivor0、Survivor1）与老年代。
- 方法区：存储已被虚拟机加载的类型信息、常量、静态变量、即时编译器编译后的代码缓存。JDK 8 用元空间取代永久代，元空间使用本地内存，不再受 JVM 堆大小限制，默认无上限，可通过 -XX:MaxMetaspaceSize 限制。

## 对象创建与内存分配

对象创建流程：类加载检查 → 分配内存（指针碰撞或空闲列表）→ 初始化零值 → 设置对象头 → 执行构造方法。

对象内存分配主要方式：栈上分配（逃逸分析）、TLAB（线程本地分配缓冲）、Eden 区分配、大对象直接进入老年代。

对象结构包含三部分：对象头（Mark Word、类型指针，数组还包括数组长度）、实例数据、对齐填充。

## 垃圾回收

### 判断对象是否可回收

- 引用计数法：有循环引用问题，主流 JVM 不采用。
- 可达性分析：以 GC Roots 为起点向下搜索，不可达对象判定为可回收。GC Roots 包括：虚拟机栈中引用的对象、方法区中静态属性引用的对象、常量引用的对象、本地方法栈中 JNI 引用的对象、被同步锁持有的对象。

### 引用类型

强引用（不回收）、软引用（内存不足时回收，适合缓存）、弱引用（下次 GC 即回收）、虚引用（不影响生命周期，用于对象回收跟踪）。

### 垃圾收集算法

- 标记-清除：效率一般，产生内存碎片。
- 标记-复制：将内存分为两块，存活对象复制到另一块并清空当前块，无碎片但浪费空间，常用于新生代（Eden 与 Survivor 8:1 比例）。
- 标记-整理：存活对象向一端移动，无碎片，适用于老年代。

### 分代收集与常用收集器

新生代：Serial、ParNew、Parallel Scavenge。老年代：Serial Old、Parallel Old、CMS。JDK 9 默认 G1，JDK 17 默认 G1，JDK 21 默认 ZGC 之前的 G1（实际 JDK 21 默认仍是 G1，ZGC 为可选项）。

G1 将堆划分为多个 Region，可预测停顿时间，通过 -XX:MaxGCPauseMillis 设置目标停顿。ZGC 基于染色指针与读屏障，支持 TB 级堆，停顿时间与堆大小无关（毫秒级），JDK 15 转正，JDK 21 仍为实验特性需解锁但已非常稳定。

### CMS 与 G1 区别

CMS 是并发标记-清除，面向老年代，会产生碎片，且并发阶段 CPU 敏感，JDK 14 移除。G1 面向整个堆的 Region 化收集，默认开启。

### GC 触发时机

Minor GC：新生代空间不足。Major GC/Full GC：老年代空间不足、元空间不足、System.gc()、CMS 并发模式失败等。

## 类加载机制

### 类加载过程

加载 → 验证 → 准备 → 解析 → 初始化，其中验证、准备、解析属于连接阶段。

- 加载：通过全限定名获取二进制字节流，在方法区生成 Class 对象。
- 验证：校验字节码文件格式、元数据、字节码、符号引用。
- 准备：为静态变量分配内存并赋零值（final 常量直接赋值）。
- 解析：将符号引用替换为直接引用。
- 初始化：执行静态代码块与静态变量赋值（clinit）。

### 双亲委派模型

类加载器层级：启动类加载器（Bootstrap，加载 rt.jar）→ 扩展类加载器（Extension，JDK 9 后为平台类加载器）→ 应用类加载器（AppClassLoader）→ 自定义加载器。

工作流程：类加载请求先委派给父加载器，父加载器无法完成时才由子加载器自己加载。

优点：避免类重复加载；保证核心 API 不被篡改（沙箱安全机制）。

打破双亲委派的方式：继承 ClassLoader 并重写 loadClass 方法（如 Tomcat 的 WebAppClassLoader、SPI 的线程上下文类加载器）。

## JVM 调优常用参数

- -Xms/-Xmx：堆初始与最大大小，生产环境建议设相同值避免扩容抖动。
- -Xmn：新生代大小。
- -XX:MaxMetaspaceSize：元空间上限。
- -XX:+UseG1GC / -XX:+UseZGC：选择收集器。
- -XX:MaxGCPauseMillis：G1 目标停顿时间。
- -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath：OOM 时自动导出堆转储。
- -XX:SurvivorRatio：Eden 与 Survivor 比例，默认 8:1。

## 常见面试问题速记

1. 什么情况下会发生 OOM？堆内存不足、元空间不足、直接内存不足、线程过多导致栈无法分配。
2. 如何排查内存泄漏？jmap 导出堆转储 + MAT/JProfiler 分析，结合 jstat 观察 GC 频率。
3. 强引用对象一定会被回收吗？不一定，取决于可达性分析结果。
4. 字符串常量池在哪？JDK 7 之前位于永久代，JDK 7 移至堆，JDK 8 仍在堆。
