# 计算机网络八股文

## 分层模型

- OSI 七层：物理、数据链路、网络、传输、会话、表示、应用。
- TCP/IP 四层：网络接口、网络（IP）、传输（TCP/UDP）、应用（HTTP/DNS）。
- 各层常见协议：HTTP/HTTPS、DNS（应用层）、TCP/UDP（传输层）、IP/ICMP/ARP（网络层）、以太网（链路层）。

## TCP 三次握手

1. 客户端发 SYN（seq=x），进入 SYN_SENT。
2. 服务端回 SYN+ACK（seq=y, ack=x+1），进入 SYN_RCVD。
3. 客户端发 ACK（ack=y+1），双方进入 ESTABLISHED。

- 为什么三次：两次无法确认客户端接收能力（防旧 SYN 失效导致服务端建立无效连接），也避免资源浪费；四次多余（第三次可携带数据）。
- SYN 洪泛攻击：半连接队列被占满，可开 syncookies。

## TCP 四次挥手

1. 主动方发 FIN，进入 FIN_WAIT_1。
2. 被动方回 ACK，主动方进入 FIN_WAIT_2，被动方进入 CLOSE_WAIT。
3. 被动方发 FIN，进入 LAST_ACK。
4. 主动方回 ACK，进入 TIME_WAIT（2MSL），被动方进入 CLOSED。

- 为什么四次：TCP 全双工，FIN 只表示本方数据发送完毕，对方可能还有数据要发，所以 ACK 与 FIN 分开。
- TIME_WAIT 2MSL：保证最后一个 ACK 可达（丢失则对端重发 FIN），并让旧连接报文在网络中消散，防止端口复用后收到旧数据。

## TCP 可靠传输与拥塞控制

- 可靠：序列号、确认应答（ACK）、超时重传、快速重传（3 个重复 ACK）、滑动窗口（流量控制，避免接收方溢出）、累计确认。
- 拥塞控制：慢启动（指数增长，阈值 ssthresh 后线性）、拥塞避免（加性增）、快速恢复、快速重传；AIMD 原则。
- 粘包/拆包：TCP 是字节流无消息边界，应用层需自定义长度字段 / 分隔符 / 定长消息。

## TCP 与 UDP

- TCP：面向连接、可靠、有序、字节流、拥塞控制，开销大；适合文件传输、HTTP。
- UDP：无连接、不可靠、无序、面向报文、低延迟；适合 DNS、音视频、游戏、QUIC 底层。
- TCP 头部 20 字节（源/目的端口、序列号、确认号、标志位、窗口等），UDP 头部仅 8 字节。

## HTTP 演进

- HTTP/1.0：短连接；HTTP/1.1：持久连接（keep-alive 默认）、管线化（有队头阻塞）、Host 头。
- HTTP/2：二进制分帧、多路复用（解决队头阻塞在应用层缓解，TCP 层仍可能队头阻塞）、头部压缩（HPACK）、服务端推送、TLS 加密默认（h2c 例外）。
- HTTP/3：基于 QUIC（UDP 实现），连接迁移、0-RTT、彻底解决队头阻塞。
- GET 与 POST：GET 幂等、参数在 URL（可缓存、有长度限制）；POST 非幂等、参数在 body。语义区别，安全性无本质差异（都可被截获）。

## HTTPS 握手（TLS 1.2 简版）

1. ClientHello（随机数、支持的加密套件）。
2. ServerHello + 证书（含公钥）→ 客户端校验证书链与域名。
3. 客户端生成预主密钥，用服务器公钥加密发送（或 ECDHE 密钥交换）。
4. 双方各自计算会话密钥（对称加密），发送 Finished 验证。
5. 之后用对称密钥加密通信。

- 混合加密：非对称（RSA/ECDHE）协商密钥 + 对称（AES）传输数据，兼顾安全与性能。
- 为什么证书：防中间人冒充，CA 数字签名保证公钥可信；证书校验失败浏览器会告警。

## 常见状态码

- 2xx：200 OK、201 Created、204 No Content。
- 3xx：301 永久重定向、302 临时重定向、304 Not Modified（协商缓存命中）。
- 4xx：400 参数错误、401 未认证、403 禁止访问、404 不存在、429 限流。
- 5xx：500 服务端异常、502 网关错误、503 服务不可用、504 网关超时。

## 输入 URL 到页面展示

DNS 解析（浏览器缓存 → 系统缓存 → hosts → 递归/迭代查询）→ TCP 连接（含 TLS）→ HTTP 请求 → 服务端处理 → 响应 → 浏览器解析 HTML/CSS/JS → 渲染与资源加载 → 断开连接。
