# 操作系统八股文

## 进程与线程

- 进程：资源分配的基本单位，拥有独立地址空间、文件、信号等资源；线程：CPU 调度（执行）的基本单位，共享所属进程的地址空间与资源。
- 线程切换开销小于进程切换（无需切换地址空间、页表、文件描述符表等）。
- 协程：用户态调度、更轻量，切换无需内核态（如 Go goroutine、Java 虚拟线程）。

## 进程状态与调度

- 状态机：新建 → 就绪 → 运行 → 阻塞 → 就绪 / 终止；就绪与运行之间可被抢占。
- 调度算法：先来先服务（FCFS，有护航效应）、短作业优先（SJF，可能饿死长作业）、时间片轮转（RR，适合分时）、优先级调度（可能饿死低优先级）、多级反馈队列（兼顾响应与吞吐）。

## 进程间通信（IPC）

- 管道（pipe 匿名 / FIFO 命名）、消息队列、共享内存（最快，需同步机制配合）、信号量（PV 操作）、信号、Socket（跨主机）。
- 线程间通信更简单：共享内存 + 锁 / 条件变量 / 信号量。

## 死锁

- 四个必要条件：互斥、持有并等待、不可剥夺、循环等待——四个同时满足才可能死锁。
- 预防：破坏任一条件（如一次性申请所有资源、资源排序）；避免：银行家算法；检测与恢复：资源分配图 + 回滚/杀死进程。

## 内存管理

- 连续分配：固定分区 / 动态分区（首次适应、最佳适应、最差适应，有外部碎片问题）。
- 分页：固定大小页，页表映射逻辑地址 → 物理地址，解决外部碎片；页表过大用多级页表 / 倒排页表。
- 分段：按逻辑模块分段，便于共享与保护，有外部碎片；段页式：先分段再分页。
- TLB（快表）：缓存最近页表项，命中可跳过内存访问页表，大幅提升地址转换速度。

## 虚拟内存与页面置换

- 虚拟内存：进程只加载部分页到内存，访问缺页时按需调入（demand paging），逻辑地址空间可大于物理内存。
- 页面置换算法：FIFO（可能 Belady 异常）、LRU（最近最久未使用，近似实现 Clock 时钟算法）、LFU、最优置换 OPT（理论）。
- 抖动（Thrashing）：进程频繁缺页、CPU 大部分时间用于换页，通过工作集模型与调入调出策略缓解。

## 用户态与内核态

- 特权指令只能在内核态执行；系统调用是用户态进入内核态的唯一安全途径（trap 中断）。
- 用户态切内核态开销：保存上下文、参数传递校验、内核执行、恢复——高频系统调用是性能热点（如 epoll 相比阻塞 IO）。

## Linux 常见机制

- 零拷贝：mmap + write / sendfile，减少内核态与用户态间的数据拷贝，Kafka、Netty 传输优化常用。
- IO 多路复用：select（fd 集合 1024 限制）/ poll（无上限但仍是线性扫描）/ epoll（事件驱动、红黑树 + 就绪链表，仅 Linux；macOS 用 kqueue）。
- epoll 两种触发模式：水平触发 LT（默认，只要有数据就通知）与边缘触发 ET（仅状态变化时通知一次，需一次读完，常配非阻塞 IO）。
- BIO/NIO/AIO：BIO 一连接一线程；NIO 基于 Selector 多路复用，非阻塞读写；AIO 异步回调（Java 中应用较少，Netty 底层仍是 NIO + epoll）。
